# monopanel · модуль «Домены» (`apps/domains`)

Модуль массового отбора доменов для панели **monopanel** (Docker-монорепо, рядом
с `apps/cf`, `apps/content`). Реализует **единый двухступенчатый пайплайн**,
собранный из двух ТЗ в одну фронтенд-панель с одной вкладкой настроек.

```
Выгрузка Ahrefs Batch Analysis
        │
        ▼
┌─────────────────────────────┐     мост      ┌──────────────────────────────┐
│  Часть 1: Ahrefs-фильтр      │  A/B/C →      │  Часть 2: Классификатор       │
│  количественный гейт         │  Targets  →   │  по имени (нейросеть)         │
│  авторитет / спам / тиры     │───────────────▶  pharma/casino/adult/язык     │
│  чистая функция, без API     │               │  good / bad / на проверку     │
└─────────────────────────────┘               └──────────────────────────────┘
        Часть 1 — реализована                    Часть 2 — следующая итерация
```

**Мост** — это суть связки: Часть 1 отсеивает мусор по ссылочному профилю и
раскладывает выжившие домены по тирам; кнопкой «Отправить тиры A/B/C →
Классификатор» их `Target` уезжают во вторую часть, где нейросеть судит уже по
названию. Две половины ТЗ — это две последовательные стадии одного отбора.

## Статус

| Часть | Что | Статус |
|---|---|---|
| 1 | Ahrefs количественный фильтр (парсинг, отсев, скор, тиры, флаги, экспорт, живой пересчёт, пресеты) | ✅ реализовано + тесты |
| Мост | Передача Targets выбранных тиров из Части 1 во вкладку Части 2 | ✅ реализовано |

## Запуск

### Через Docker (как в monopanel)
```bash
docker compose up --build
# панель:  http://localhost:8080
```

### Локальная разработка
```bash
# backend
cd apps/domains/backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload            # :8000

# frontend (в другом терминале)
cd apps/domains/frontend
npm install
npm run dev                              # :5173, проксирует /api на :8000
```

### Тесты
```bash
cd apps/domains/backend && . .venv/bin/activate && pytest -q
```

## Ключевые принципы реализации Части 1

- **Ранжирование, не бинарный отсев.** Жёстко режется только явный мусор (~6%);
  всё остальное скорится, а финальную границу ставит пользователь порогом/топ-N.
- **Чистая функция.** `analyze(records, config)` не имеет побочных эффектов —
  поэтому смена любого параметра в «Настройках» пересчитывает результат
  **без повторной загрузки** (§9): бэкенд держит распарсенные строки в памяти
  и лишь заново прогоняет пайплайн.
- **Всё в конфиге.** Веса, cap-константы, пороги отсева, границы тиров, наборы
  флагов — редактируются из UI, валидируются (веса ≥ 0, тиры монотонны),
  сохраняются в пресеты.
- **Загрузчик — мост форматов.** Ahrefs отдаёт один и тот же экспорт в двух
  формах (UTF-16/таб, UTF-8/запятая); `loader.py` приводит обе к одному
  набору полей по **имени заголовка**, а не по индексу.

## API (Часть 1)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/ahrefs/datasets` | загрузка файла выгрузки |
| POST | `/api/ahrefs/datasets/rows` | приём уже загруженных строк (JSON) |
| POST | `/api/ahrefs/datasets/{id}/analyze` | пересчёт под конфиг |
| POST | `/api/ahrefs/datasets/{id}/export` | CSV / TXT |
| POST | `/api/ahrefs/datasets/{id}/targets` | **мост**: Targets выбранных тиров |
| GET  | `/api/config/default` | дефолтный конфиг |
| POST | `/api/config/validate` | валидация (предупреждения) |
| GET/POST/DELETE | `/api/config/presets…` | пресеты |

## API (Часть 2)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/classify/preview` | счётчики распознано/дубли/невалидные |
| POST | `/api/classify/runs` | старт прогона (фоновый async) |
| GET  | `/api/classify/runs/{id}` | прогресс + бакеты (инкрементально) |
| POST | `/api/classify/runs/{id}/cancel` | отмена |
| GET  | `/api/classify/runs` | история прогонов |
| GET  | `/api/classify/runs/{id}/logs` | логи прогона |
| POST | `/api/classify/runs/{id}/export` | CSV / TXT (бакет или всё) |
| GET/PUT | `/api/classify/settings` | AI-настройки (ключи маскируются) |

> **Провайдеры.** OpenAI (основной) и OpenRouter (резерв) — через единый
> OpenAI-совместимый клиент; ключи задаются в «Настройках» → AI и хранятся
> на стороне панели (маскируются, не в логах). Провайдер `mock` — офлайн-демо
> без сети/ключей для проверки оркестрации.
